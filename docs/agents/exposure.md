# Exposure pipeline

This file holds the rules of the exposure pipeline. The file `exposure/policy.yaml` holds each number, each list, each header value, and each path. A rule names a key of that file and not a value. If a rule and the policy file disagree, the policy file wins. Then correct the rule.

The pipeline controls what an anonymous visitor gets from a deployed build. It has four parts. The access rules of the data layer and the authorization of each route are two. The set of files that the host serves and the headers of each response are the other two. The visitor is anonymous, so each rule starts from no access. A rule then names the one thing that the visitor can get.

## When a gate is red

1. Stop. Change the policy file, a route record, or a deviation record only when the `Do:` line of the no-go line names that file. Do not change an adapter by hand.
2. Run `pnpm explain <ID>` with the identifier that the no-go line names. Read the damage and the test.
3. Do the one action of the no-go line. It starts with `Do:`.
4. Run the gate again, with `pnpm exposure <gate>`.
5. If the gate stays red after two tries, stop. Give the user the no-go lines. Do not try a third time.

## What this file does not own

- `docs/agents/security.md` owns the deviation machinery, the change control, and the conduct of the agent. It owns the secrets of the source tree and the dependencies. Its Rule CODE-04 points at Rule HDR-02 for the content security policy of the page.
- `docs/agents/accessibility.md` owns the test of the words of each rule file.
- `docs/agents/bundle.md` owns the list of the routes, the build of the output, and the maps. Rule MAP-01 keeps each map in the output, and this pipeline keeps each map out of the served set.
- `docs/agents/resilience.md` owns the error of a route and the one client that calls `fetch`.
- `bulletproof-pr` owns the text of a commit message and a pull request. `bulletproof-issue` owns the text of an issue.
- `tiger-style` owns the shape of the code. `penno` owns the tests.

If a rule here and one of these files disagree, the other file wins. Then correct the rule here.

## How to read a rule

The section "How to read a rule" of `docs/agents/security.md` gives the identifier, the category, the layer, the cause, and the test. It also gives the rule that no answer is no-go. A rule of this file uses the same names.

A no-go line of this pipeline has three parts. The symptom, one action after the word `Do:`, and the rule. The action is safe in each state. Rule ESOT-08 gives the shape.

## Eight words

This file uses eight words for eight things, and it does not interchange them.

- An anonymous visitor is a request with no cookie, no token, and no header that the server set. The probe suite is one.
- The header set is the list of headers that `scripts/exposure/headers.ts` makes from `headers` of the policy file. Each response has it.
- A route is a path of `exposure/routes.yaml`. Its record names the audience.
- The audience of a route is the group that can get it. `public` is the audience of the anonymous visitor.
- The output is the folder that `vite build` writes, `output.dir`.
- The served set is each file of the output minus each file of `output.skip`. The host serves the served set and nothing else.
- An adapter is a file in `exposure/adapters/` that gives the header set in the syntax of one host. The gate `adapters` writes each adapter, and no person edits one.
- The probe is the suite `probe.suite`. It is the anonymous visitor of the preview server and of the deployed URL.

## 1 Source of truth

- **ESOT-01 (M, proven).** Each number, each list, each header value, and each path of the pipeline lives in `exposure/policy.yaml`. The function `headerSetOf` in `scripts/exposure/headers.ts` is the one function that turns the policy file into the header set. The preview server, each adapter, and the probe read that one function. The shape of a hashed name lives in the bundle pipeline, in `HASH` of `scripts/bundle/measure.ts`. Cause: RFC 8785 gives one canonical form, so that two writers get the same bytes. Two copies of a value become different. Test: `pnpm exposure:policy` refuses a number that is not a positive integer, a path that names no file, and a key that it does not know.
- **ESOT-02 (M, proven).** The command `pnpm exposure` is the one entry point. It runs each gate in the sequence that `gates` gives. `gates` holds `policy`, `data`, `adapters`, `output`, and `probe`. It holds `live` only when `live.url` holds a URL. CI runs this one command, with no `continue-on-error`. The pre-push hook runs the gates `policy`, `data`, and `adapters`, because the gate `output` builds and the gate `probe` starts a browser. Cause: a gate that CI runs and the laptop does not is a gate that no person sees before the push. Test: `pnpm exposure:policy` reads the workflow file. It has one exposure step, and that step is `pnpm exposure`.
- **ESOT-03 (R, proven).** A value of the policy file moves only in the safe direction with no deviation record. A shorter list of served extensions, of dot folders, and of audiences is safe. A shorter list of sources in a directive of `headers.csp` is safe, and a new directive counts as a longer list. A longer list of denied permissions, of missing headers, and of probe paths is safe. The values of `headers.fixed` and of `headers.cache` do not move, because Rules HDR-03, HDR-05, and HDR-09 fix them. A smaller file count, a smaller file size, and fewer deviation days are safe. Cause: SEC Rule 15c3-5. A control that loosens near a deadline is not a control. Test: `pnpm exposure:policy` compares the policy file with the file on `origin/main`.
- **ESOT-04 (M, proven).** A change to `exposure/policy.yaml` is its own pull request. It touches no other file. A new route record goes in `routes.file`, so it can go with the page that it names. Cause: a limit that moves in the same commit as the code that broke it hides the break. Test: `.githooks/pre-push` refuses a branch that changes the policy file and one more file.
- **ESOT-05 (M, proven).** A rule identifier of this file is not removed, not used again, and not renumbered. A rule that no longer applies keeps its identifier and gets the layer `retired`, with the cause of the retirement. Cause: the Sandia report SAND92-1382 on the markers of a waste site. A stable identifier lets an earlier reader and a subsequent reader point at the same thing. Test: `pnpm exposure:policy` compares the identifiers of this file with the file on `origin/main`. A missing identifier is no-go.
- **ESOT-06 (M, proven).** Each configuration file of this pipeline starts with a comment that holds the word `DANGER:`. The comment names what an anonymous visitor gets when a value is incorrect. The policy file, the routes file, the deviations file, the gitleaks file, and each adapter that is not JSON are the configuration files. JSON holds no comment, and the gate `adapters` guards `vercel.json`. Cause: the principles of the 10,000 Year Clock put the manual on the object itself. A file with its own warning is complete without a reader who remembers it. Test: `pnpm exposure:policy` reads the first five lines of each file.
- **ESOT-07 (M, proven).** The cause of a rule of this file cites a public document or names the damage. It cites no chat, no ticket, no person, and no memory. Cause: SAND92-1382 plans for no active institutional control. A reader in ten years has no access to the chat. Test: `pnpm exposure:policy` refuses a rule line that holds a handle, a ticket number, or a phrase that points at a memory.
- **ESOT-08 (M, proven).** A no-go line of this pipeline has three parts in this sequence. The symptom, the word `Do:` with one action in the imperative, and the rule. The action is safe in each state and is correct without a diagnosis. Cause: the AED voice prompts and the ATLS primary survey. A reader in an emergency gets the symptom and one action, not a diagnosis. Test: the function `problem` in `scripts/exposure/shared.ts` is the one maker of a no-go line, and it refuses a line of a different shape.

## 2 The header set

- **HDR-01 (M, proven).** Each response has the header set, byte for byte. Each name is lowercase and occurs one time. The names are in alphabetical sequence. The response of a route, of a hashed file, of an unknown path, and of each probe path has the same set. Cause: RFC 9110 section 5.3. A parser joins two lines of one name, and each parser does it in a different manner. nginx `add_header` without `always` drops each header on a 404. Test: the probe compares the headers of each response with the header set, and it refuses a name that occurs two times.
- **HDR-02 (M, proven).** The content security policy has each directive one time, in alphabetical sequence. It holds `base-uri 'none'`, `object-src 'none'`, `frame-ancestors 'none'`, `form-action 'self'`, `default-src 'self'`, and `require-trusted-types-for 'script'`. When `server.kind` is not `none`, `script-src` holds `'strict-dynamic'` and the server mints a nonce per response. A static build cannot mint a nonce, so it ships `script-src 'self'` and the hashes of Rule OUT-03. No directive holds `'unsafe-inline'`, `'unsafe-eval'`, `*`, `http:`, or `https:`. The policy goes in a header and not in a `meta` tag. The page of the route `/` logs no policy violation. Cause: CSP Level 3 section 2.2.1 lets the first of two directives win. The web.dev strict policy. A `meta` tag drops `frame-ancestors`. Test: `pnpm exposure:policy` parses `headers.csp`. `pnpm exposure:output` refuses an html file with `http-equiv`. The probe reads the console of the page.
- **HDR-03 (M, proven).** `strict-transport-security` is `max-age=63072000; includeSubDomains; preload` on each response. Cause: the requirements of hstspreload.org. Test: `pnpm exposure:policy` compares the value. The probe reads the header.
- **HDR-04 (R, attested).** After the first deploy, the user sends the domain to hstspreload.org. Cause: a preload entry holds when the header is gone. A domain that is not on the list has a first visit with no protection. Test: the user reads the deploy step of the setup list in `README.md`.
- **HDR-05 (M, proven).** The header `x-frame-options` is `DENY`. `x-content-type-options` is `nosniff`. `referrer-policy` is `no-referrer`. `cross-origin-opener-policy` is `same-origin`. `cross-origin-embedder-policy` is `require-corp`. `cross-origin-resource-policy` is `same-origin`. The page of the route `/` reads `crossOriginIsolated` as `true`. Cause: the header project of OWASP, OSHP. The two cross-origin headers isolate the page only together. Test: `pnpm exposure:policy` compares each value. The probe reads `crossOriginIsolated`.
- **HDR-06 (M, proven).** `permissions-policy` denies each feature of `headers.permissions_denied` with an empty allowlist. A project that uses one feature removes it from the list. That removal is the dangerous direction of Rule ESOT-03. Cause: the header project of OWASP, OSHP. A feature that no page uses is a feature that the script of an attacker uses. Test: `pnpm exposure:policy` compares the value. The probe reads the header.
- **HDR-07 (M, proven).** No response has a header of `headers.absent`. `server`, `x-powered-by`, and `x-xss-protection` are three of them. Cause: `x-xss-protection: 1` opens a leak in an earlier browser, and helmet sends `0`. The name of the server is a map for an attacker. Test: the probe reads each response.
- **HDR-08 (M, proven).** No response has `access-control-allow-origin`. The name is in `headers.absent`. A project with a reader on a different origin adds the header in its server, for the named origins, with `vary: origin`. A host adapter of this pipeline cannot name an origin. Cause: the Fetch standard. A reflected origin with credentials gives each site the data of the user. Test: the probe sends `origin` with `probe.foreign_origin` and refuses the header.
- **HDR-09 (M, proven).** A served file with a hashed name, as `HASH` of `scripts/bundle/measure.ts` defines it, gets `cache-control` `headers.cache.hashed`. Each other file, the html too, gets `headers.cache.other`. Cause: RFC 8246 gives `immutable` to a file with a URL that changes with its content. A stale html is a second version of the site. Test: the probe reads the header of the route `/`, of a hashed file, and of each unhashed file of the served set.
- **HDR-10 (M, proven).** No response of a static build has `set-cookie`. When a server sets a cookie, its name starts with `__Host-`. It has `Secure`, `HttpOnly`, `Path=/`, and `SameSite=Lax` or `SameSite=Strict`. It has no `Domain`. Cause: RFC 6265bis, the cookie prefixes. Test: the probe parses each `set-cookie`.
- **HDR-11 (R, proven).** The `content-type` of an html response is `headers.html_content_type`. Cause: `nosniff` of Rule HDR-05 makes an incorrect type a blocked file. Test: the probe reads the header of the route `/`.

## 3 Routes

- **ROUTE-01 (M, proven).** Each route of `bundle/policy.yaml` has one record in `routes.file`. The path starts with `/`, and no path has two records. The audience is `public` or a name of `routes.audiences`. The branch that adds a page adds its record. Cause: OWASP Top 10 2021, A01. A route with no record has no audience, and a route with no audience is denied. Test: `pnpm exposure:policy`.
- **ROUTE-02 (M, proven).** In a static build each path is public. A record with an audience other than `public` is refused while `server.kind` is `none`. Cause: a static host serves each file to each visitor. SvelteKit runs no hook for a prerendered page. A client guard is a redirect and not a denial. Test: `pnpm exposure:policy`.
- **ROUTE-03 (M, proven).** The probe gets each route as the anonymous visitor. A public route answers 200. A route of a different audience answers `routes.anonymous_status`. A method that the record does not list answers `routes.method_status` with an `allow` header. `HEAD` gets the status of `GET`. Cause: the OWASP authorization cheat sheet. 404 hides that the route exists. A `HEAD` that skips the check leaks the status. Test: the probe.
- **ROUTE-04 (M, proven).** An unknown path with a dot segment or a file extension answers 404. It does not get the fallback page. An unknown path with no extension gets the fallback page, with the body of the route `/` and the full header set. Cause: a fallback that answers 200 for each path hides a missing file from each scanner. Test: the probe gets each path of `probe.paths` and three unknown paths.
- **ROUTE-05 (M, proven).** A server has one module that selects the access, `server.authorize`. Each file of `server.handlers` imports it. A header, a cookie, or a query of the client does not turn a check off. Cause: CVE-2025-29927. One request header skipped the middleware of Next.js. Saltzer and Schroeder call it complete mediation. Test: `pnpm exposure:policy` reads each handler file. The probe sends `x-middleware-subrequest` to each route and refuses a different status.
- **ROUTE-06 (M, attested).** The audience of a record is the intent of the product. `robots.txt` and a client guard are not access control. Cause: Saltzer and Schroeder, open design. A path that no index lists stays a path. Test: the user reads each new record of `routes.file` in the review.
- **ROUTE-07 (M, proven).** `robots.txt` and `sitemap.xml` of the served set name no route of an audience other than `public`. Cause: `robots.txt` is public, and it is a list of targets. Test: `pnpm exposure:output` reads the two files when they exist.
- **ROUTE-08 (M, attested).** A record with a parameter in its path names its `scope`, one of `routes.scopes`. The handler of that route reads the row with the identifier and the caller together, and not with the identifier alone. Cause: the OWASP cheat sheet on insecure direct object references. An identifier that no one can guess is not an authorization. Test: `pnpm exposure:policy` refuses a record with a parameter and no scope. The user reads the query of each handler in the review.

## 4 The data layer

- **DATA-01 (M, proven).** `data.kind` names the data layer. It is `none`, `postgres`, or `firestore`. A package of `data.packages` of a different type in `package.json` is refused, and a package of `data.packages.unsupported` is refused until this file holds its rules. A served file that names a host of `data.hosts` of a different type is refused. A host of `data.hosts.unsupported` is refused until this file holds its rules. Cause: a data layer that no rule names has no rule. Test: `pnpm exposure:data` reads `package.json`, and `pnpm exposure:output` reads each served text file.
- **DATA-02 (M, proven).** For `postgres`, each `create table` of `data.postgres.migrations` has `enable row level security` and `force row level security` for that table in the same file. No file has `disable row level security` or `no force row level security`. Cause: the PostgreSQL manual, chapter 5.9. The owner of a table skips the policies until the table is forced. CVE-2025-48757 exposed 170 projects that had the anon key and no policy. Test: `pnpm exposure:data` parses each migration.
- **DATA-03 (M, proven).** For `postgres`, no policy has `using (true)` or `with check (true)` for the role `anon` or `public`. No `grant` gives the role `anon` more than `select` on a table of `data.postgres.anon_readable`. Cause: the Supabase database linter, lint 0024. A policy that is always true is no policy. Test: `pnpm exposure:data` parses each migration.
- **DATA-04 (M, proven).** For `postgres`, each `create view` sets `security_invoker = true`. Each `security definer` function sets `search_path`. Cause: the Supabase database linter, lints 0010 and 0011. A view runs with the rights of its owner and skips each policy. Test: `pnpm exposure:data` parses each migration.
- **DATA-05 (M, proven).** For `postgres`, each table of `data.postgres.anon_readable` has a test file in `data.postgres.tests` that sets the role `anon` before its assertions. Cause: a test as the superuser skips each policy and proves nothing. Test: `pnpm exposure:data` reads each test file.
- **DATA-06 (M, proven).** For `firestore`, the rules file `data.firestore.rules` ends with a match of each document that denies read and write. No rule holds `if true`. The test file `data.firestore.tests` calls `unauthenticatedContext`, and it calls `assertFails`. Cause: the Firebase documentation of the rules unit tests. The 2024 scan of Firebase found 125 million records open to the anonymous visitor. Test: `pnpm exposure:data` reads the two files.
- **DATA-07 (M, proven).** The served set holds no secret of the data layer. A JSON web token with the role `service_role` in its payload is one. A key that starts with `sb_secret_`, a private key block, and a URL with a password are three more. Cause: the Supabase documentation of the API keys. The secret key skips each policy. Test: `pnpm exposure:output` reads each served file.
- **DATA-08 (M, attested).** The tests of the data layer run on a real engine, as the role `anon`. A mock of the engine does not count. Cause: the PostgreSQL manual, chapter 5.9. The superuser skips each policy. Test: the user runs `supabase test db` or the Firebase emulator before each release and reads the result.

## 5 The served set

- **OUT-01 (M, proven).** The gate `output` builds `output.dir` with `vite build` in production mode. The served set is each file of that folder minus each file of `output.skip`. Each served file has an extension of `output.served_extensions`. Cause: OWASP WSTG-CONF-04. A backup, a dump, and an editor file ship through an unknown extension. Test: `pnpm exposure:output` walks the folder.
- **OUT-02 (M, proven).** No path segment of a served file starts with a dot. A folder of `output.dot_allowed` is the one exception. Cause: the scans of 2024 and 2025 that fetched `/.git/` and `/.env` from public hosts. Test: `pnpm exposure:output` walks the folder.
- **OUT-03 (M, proven).** No served html file holds an inline script body or an attribute that starts with `on`. It holds no `javascript:` URL and no `meta` tag with `http-equiv`. Each `style` tag of the html has its hash in `headers.csp.style-src`, and each hash there has a `style` tag. Cause: the strict policy of Rule HDR-02 blocks an inline script, so a page that has one is a broken page. A blocked `style` tag shows the fallback text with no delay. Test: `pnpm exposure:output` reads each served file.
- **OUT-04 (M, proven).** Each served file in `assets/` has a hashed name, as `HASH` of `scripts/bundle/measure.ts` defines it. The served set has at most `output.files_max` files, and no file has more than `output.file_bytes_max` bytes. Cause: only a hashed name can be immutable. A file count that jumps is the cheapest sign of a leaked folder. Test: `pnpm exposure:output`.
- **OUT-05 (M, proven).** `gitleaks dir` on the served set finds no secret, with the rules of `output.gitleaks_config`. That file turns the generic token rule off, because a client bundle ships the anon token on purpose. Rule DATA-07 reads the role of each token. A missing `gitleaks` is no-go. Cause: Vite puts each `VITE_` variable into the bundle. A gate that cannot run is a gate that passed nothing. Test: `pnpm exposure:output` runs `gitleaks`.
- **OUT-06 (M, proven).** The gate writes `output.manifest` with the path, the byte count, and the SHA-256 of each served file, in alphabetical sequence. Cause: the Subresource Integrity standard. The identity of a file is its hash, so a host can be compared with the list. The probe compares the body of each served file of `assets/` with its hash in the list. Test: `pnpm exposure:output` writes the file. The probe and the gate `live` read it.
- **OUT-07 (M, attested).** The deploy uploads the files of `output.manifest` and nothing else. The host lists no folder. Cause: a host serves each file that it holds. Test: the user reads the deploy step of the setup list in `README.md`, and the gate `live` gets each path of `probe.paths`.
- **OUT-08 (R, proven).** When `live.url` holds a URL, the served set holds `output.security_txt.path` with a `Contact` line and an `Expires` line. The expiry is between `expires_days_min` and `expires_days_max` days away. Cause: RFC 9116, section 2.5. Test: `pnpm exposure:output` parses the file.
- **OUT-09 (M, proven).** The `envPrefix` of Vite stays at its default, `VITE_`. A `VITE_` name that holds a secret word stops the build. Cause: the Vite documentation of the environment variables. An empty prefix ships each variable of the machine. Test: `vite.config.ts` refuses the build through `refuseShippedSecret`, and `pnpm exposure:output` refuses a `vite.config.ts` that sets `envPrefix`.

## 6 The probe

- **PROBE-01 (M, proven).** The suite `probe.suite` runs against the preview server of the served set. It writes one record per response to `probe.report`. A suite that fails and a report that is missing are no-go. Cause: 49 CFR 236.5, the closed-circuit principle. A signal with no power shows the most restrictive aspect. Test: `pnpm exposure:probe`.
- **PROBE-02 (M, proven).** Each path of `probe.paths` answers 404 with the full header set. Cause: TMI. Read the real state of the plant, not the position of the switch. Test: the probe.
- **PROBE-03 (M, proven).** When `live.url` holds a URL, `gates` holds `live`, and the gate runs the suite against that URL. When `live.url` is empty, `gates` does not hold `live`. Each hashed file of `output.manifest` answers 200, and its map path answers 404. Cause: water got into the Svalbard seed vault in 2017 because of an assumption that no one tested. The workflow lets the runner out to the host of `live.url`. Test: `pnpm exposure:policy` compares the two keys, and it reads `allowed-endpoints` of the workflow. `pnpm exposure:live`.

## 7 Deviations

- **EDEV-01 (M, proven).** A deviation from a rule of this file is a record in `exposure/deviations.yaml`. Rules DEV-01 to DEV-03 of `docs/agents/security.md` give its seven fields, its approval, and its expiry. The field `place` names one route, one header name, one path, or one key of the policy file. Cause: GSFC-STD-1000 gives a waiver for the named elements only. Test: `pnpm exposure:policy` refuses a record with a missing field, a pattern in `place`, a past expiry, or a mandatory rule.

## 8 When a gate is red

- **RED-01 (M, proven).** Before an edit of `exposure/policy.yaml`, `exposure/routes.yaml`, or `exposure/deviations.yaml`, the agent runs `pnpm explain <ID>`. The identifier is the one of the no-go line. Cause: the challenge-response checklist of FAA AC 120-71B. The reader reads the rule before the reader changes the number. Test: `.claude/hooks/exposureExplainGate.py` refuses the write while the transcript holds no such command.
- **RED-02 (M, proven).** No person and no agent edits a file of `exposure/adapters/`. `pnpm exposure write` writes each adapter from the policy file. Cause: PEP 20. One obvious procedure for each thing. A hand edit is a second copy of the header set. Test: `.claude/hooks/exposureExplainGate.py` refuses the write, and `pnpm exposure:adapters` refuses a file that is different from the generated text.
- **RED-03 (M, attested).** When a gate is red and the agent does not know the cause, the agent does these steps in this sequence. Run `pnpm explain <ID>`. Revert the last change of the agent. Run the gate again. If the gate stays red, stop and give the user the no-go lines. Cause: the Google SRE book, chapter 13. Get one more person. Test: the user reads the transcript.
- **RED-04 (M, attested).** A change to the policy file, a deviation record, or an adapter does not make a red gate green. That change does not go in the pull request that made the gate red. Cause: the Google SRE book, chapter 14. The person who judges is not the person who changes. Test: Rule ESOT-04 proves the policy file. The user reads the diff for the deviation file.
